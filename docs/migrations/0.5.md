# Migrating to Nagi CSS 0.5

Nagi CSS 0.5 tightens stacking diagnostics while allowing component roots to
establish an internal containing block.

## Top-layer stacking

The `top-layer-z-index` rule now reports `z-index` only when the selector itself
requires a top-layer state through `:modal` or `:popover-open`. A `dialog` tag or
`popover` attribute alone does not prove that the element is currently in the
top layer.

Remove `z-index` from selectors that are explicitly limited to a top-layer
state. Keep ordinary stacking declarations on non-modal dialogs and inactive
popover surfaces when the component needs them outside the top layer.

## Surface containing blocks

A surface root may now use `position: relative` when an owned absolutely
positioned descendant needs that root as its containing block. Insets on the
surface root remain external-layout violations.

## Component configuration names

Configured component, intrinsic-component, and transparent-component names are
matched against their canonical kebab-case template spelling. Existing
UpperCamelCase configuration entries such as `DataTable` therefore match
`<data-table>` without requiring duplicate entries.

Duplicate spellings are unnecessary. Identical aliases remain accepted for
migration compatibility, but mappings that canonicalize to the same tag and
resolve to different values are a configuration error. For example,
`DataTable: "ui-data-table"` cannot coexist with
`"data-table": "legacy-data-table"`.
