# Migrating to 0.8

Roles and purposes now accept independent `layer` and `declaration` fields.
Omitting them is equivalent to `layer: "implementation"` and
`declaration: "optional"`. Existing definitions remain supported.

Use `layer: "contract"` to identify shared contract vocabulary. This metadata
does not change class names, make declarations mandatory, or certify tests.

Prefer `declaration: "required"` over `required: true`, and
`declaration: "optional"` over `required: false`. The boolean remains supported;
contradictory old and new settings are errors. Explicit and omitted defaults
compose identically. Different layers or declaration settings conflict.

Required declarations are checked within statically analyzable owned scopes,
not for visibility in every runtime state. Lint continues to check syntax,
references, naming, target constraints, and ownership. It does not associate
declarations with behavior bindings or prove correct runtime DOM placement.
Component libraries should test the declared elements themselves for structure
and behavior. No binding configuration or test framework is required for casual
Nagi CSS use.

This release does not change the ARIA uncertainty diagnostics introduced in
0.7. Consumers upgrading from older versions should also follow the
[0.7 migration](0.7.md), especially for dynamic or spread-provided ARIA roles.
