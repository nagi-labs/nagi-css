# Migrating to 0.7

Roles determine base classes. Purposes determine static variants. Existing HTML
class mappings, built-in vocabulary, structural tiers, and ownership are unchanged.

## Separate roles from purposes

Keep custom base definitions in `scopes.<scope>.roles` and their
`data-role="scope/name"` markers. Keep `data-role="scope/root"` for scope roots.
Keep standard `native: true` requirements in their ordinary HTML/ARIA form.

Move a declaration that describes an existing element's use to
`scopes.<scope>.purposes`. Change its marker to `data-purpose="scope/name"` and
add the static `-name` variant. For example:

```html
<button class="button -trigger" data-purpose="popover/trigger">Open</button>
```

A purpose may omit its role constraint, use `role: { "element": "button" }` to
require that HTML element, or use `role: { "aria": "button" }` to require
provable standard semantics. Purpose requirements do not supply behavior.
Migrate CSS selectors and behavioral test locators together. Custom roles on
native nodes no longer silently preserve an unrelated base: they report
`scoped-role-conflict`. No automatic class-only migration is performed.

## API and diagnostic names

- `createIdentityReport` becomes `createRoleReport`.
- `analysis.identities` becomes `analysis.roles`.
- `IDENTITY_RULES` becomes `ROLE_RULES`.
- Measurement JSON uses version 3 and includes `purposeDefinitions` separately
  from custom base definitions. Purpose declarations do not inflate base coverage.

Update explicit diagnostic overrides:

| Previous ID | Current ID |
| --- | --- |
| `single-base-identity` | `single-base-role` |
| `identity-format` | `role-format` |
| `role-identity-required` | `aria-role-class-required` |
| `scoped-role-identity-required` | `scoped-role-base-required` |
| `unregistered-semantic-identity` | `unregistered-semantic-role` |
| `unverifiable-role-identity` | `unverifiable-aria-role` |

Source/file identity remains an ownership concept, not a role. The
`owned-component-identity` diagnostic is unchanged. No legacy aliases silently
reinterpret declarations. Upgrade core, plugin, and CLI together.

See the [definition reference](../definitions.md) for syntax, composition,
static-analysis limits, and package loading.
