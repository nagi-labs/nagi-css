Nagi CSS

CSS, after the wind.

A lint-enforced semantic contract — every class name has exactly one correct answer.

Nagi (凪, “NAH-ghee”) is Japanese for the calm when the wind dies down — the state a codebase reaches when naming entropy stops. (Yes, the linter is a bit naggy. That’s the point.)

Every name is derived

One component, named entirely by rule. Nothing below was invented — each class comes from a lookup, and the linter enforces every derivation. The result reads as plain, unforced semantics.

  • Surface — from the file name

    invoice-card is the component file's name, kebab-cased. Never chosen.

  • Elements — from the tag

    header, title, image, list, term, definition, note, footer, button — each HTML element has one fixed class.

  • UI anatomy — a tiny allowlist

    Names for common UI parts that HTML has no tag for: field (label + control), value, actions, media, icon by default — five words go a long way, and the list is configurable per project.

  • Structural Tier Names (STN)

    A structural ladder (unit · seg · fr · g) for the divs that nothing else fits — the tier is determined by depth, so wrapper and inner never appear.

  • Variants — modifiers, not names

    -user, -primary, … — they qualify an anchor, never name what an element is, and stay alphabetical.

  • State — attributes, not classes

    disabled, aria-*, data-* — runtime state never becomes a class.

Why

The property everything else falls out of is canonical form: given the markup, the correct class for a node is unique — derived from the file name, the element and component tables, and a structural ladder, rather than chosen.

  • Machine-checkable

    A linter can verify every derivation: template classes, selector structure, ownership edges, UI-library boundaries. Consistency stops being a discipline problem.

  • Convergent

    Two authors — or an AI agent — arrive at the same class names for the same markup. Generated CSS stops drifting.

  • Meaning in the source

    class="user-card" self-documents. Diffs are a changed property in a named rule, not a mutated utility string.

Usage

The CLI accepts configuration from outside the application being checked, so a target repository needs no lint setup of its own. 

nagi-css check \
  --config /absolute/path/to/nagi.config.mjs \
  --cwd /absolute/path/to/application

ESLint validates templates and cross-block contracts; Stylelint validates selectors and CSS nesting. --fix applies only unambiguous missing fixed-class fixes. The toolchain targets Vue single-file components first; the contract itself is framework-agnostic.

Built for AI agents

The repository ships an agent skill that packages the contract as a workflow: what to derive, in what order, and how to verify the result. An agent applies the skill; the linter proves the output conforms. Generate against a deterministic contract, then machine-check it — that loop is how AI-written CSS stays consistent at scale.
